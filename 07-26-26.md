# CELLTOWER Substrate / Presentation Separation
## Design Specification for Forensic Integrity Overhaul

**Status:** Locked design — ready for implementation  
**Date:** 2026-07-26  
**Author:** Aaron Hightower (High Tower District)  
**Target audience:** Any frontier-model AI (including Grok expert) tasked with implementing the change

---

### 1. Problem Statement

`index.html` and `ck.html` currently diverge in how they turn a recorded placement `(rot, x, drop_y)` into visible piece movement.  

- `ck.html` reconstructs a plausible path using contemplation phases, BFS (`findPath`), state-to-ops conversion, and timing budgets.  
- `index.html` uses the live navigation primitives.  

On complex high-score games (~750 k) the reconstructed path produces incorrect intermediate visuals and occasional path-finding failures. This is a presentation problem that has leaked into the forensic path.

The cryptographic hash chain and board-state machine must remain completely independent of any visual path reconstruction.

---

### 2. Design Goals

1. Make the pure simulation substrate the single source of truth for every checksum and every forensic board state.
2. Allow the two HTML files to diverge freely in presentation without ever affecting a hash or a final board state.
3. Keep intentional duplication limited strictly to the substrate code that must be identical for forensic purposes.
4. Enable human frame-by-frame inspection via a derived text layer that cannot alter the substrate.
5. Produce a clean, machine-checkable boundary so a source checksum can be computed over only the substrate text.

---

### 3. Core Design Principle (Locked)

There is one pure substrate.  
It is the only code the source checksum ever sees.  
Both files embed that identical substrate.  
Tournament management + player decisions are the only inputs.  
The substrate produces board words and the terminal hash.  
Everything that makes the pieces move prettily, or that renders a human-readable trace, lives outside the barrier and cannot write back.  
Visual failure is allowed; forensic failure is not.

---

### 4. Detailed Specification

#### 4.1 Exact Checksum Surface

The substrate consists solely of the pure functions required to:

- derive the piece sequence from the seed (xoshiro128** or current PRNG)
- apply a placement and clear lines (`_vApply` + line-clear logic)
- convert the board to the 16-bit × 25 word array (`_vBoardToWords`)
- construct the 56-byte hash record and advance the chain
- any rule tables that affect final state (gravity curve, rotation system, scoring constants, line-clear order)
