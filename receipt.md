# CELLTOWER Score Receipt System

## Overview

CELLTOWER implements a self-contained, cryptographically verifiable score receipt system. No server is required. No external authority is trusted. The game itself generates an unforgeable proof of every game that occurs, visible in every frame.

A screenshot is a receipt.

-----

The receipt system was not designed in the abstract. It was designed by someone who has personally witnessed sophisticated cheating across multiple competitive gaming contexts spanning 25+ years — arcade cash competitions, online linked cabinet tournaments, and the high-stakes world record scene documented in *King of Kong*.

-----

## Why This Exists — The Threat Model

When cash is on the line — or even just the claim of being the best in the world — people will lie, cheat, and manipulate records persistently and sophisticatedly. This is not a theoretical concern. It is a documented historical pattern:

- In 1999, cash prize arcade competitions attracted players who were primarily sophisticated exploit hunters, not skilled competitors. Cheating was the dominant strategy.
- The competitive Donkey Kong scene sustained fraudulent world records for years because verification infrastructure had gaps that weren’t apparent until forensic reconstruction was applied after the fact.
- Weak verification doesn’t prevent cheating. It only delays discovery — often by years, often after reputational and financial damage has already occurred.

The CELLTOWER receipt system is designed so that a fraudulent score **cannot be constructed** from the beginning — not detected after the fact. The lie has nowhere to hide because the proof is generated by the game itself, frame by frame, in real time.

**The specific attack vectors this system defends against:**

- **Bug exploitation** — unintended game states that produce scores the hash would validate as legitimate because the inputs were technically valid. Mitigated by: CELLTOWER was written from scratch by the same person who designed the receipt system. There is no inherited code with unknown vulnerabilities.
- **Replay manipulation** — submitting a modified or fabricated replay. Mitigated by: the RNG seed and complete input log are hashed together. A modified replay produces a different hash.
- **Score injection** — claiming a score without a corresponding game. Mitigated by: the hash chain requires a valid game history. You cannot produce the correct final hash without having played the correct sequence of inputs.
- **Screenshot fabrication** — editing a screenshot to show a false score or false QR code. Mitigated by: the QR code contains the complete data structure. Verification independently reconstructs the game from the encoded data and checks it against the hash.

-----

## Design Philosophy

This system is the antidote to a model that extracts value from players through psychological exploitation — variable rewards, artificial scarcity, pay-to-win mechanics. In that model, spending determines position and skill is irrelevant to outcome.

CELLTOWER inverts every one of those premises:

- Spending has zero influence on outcome
- Position is determined exclusively by verifiable skill
- The proof of that skill is owned by the player, not the operator
- Economic value flows to the skilled player, not from the vulnerable one

Skill is the only valid currency in this system. The receipt is the proof.

-----

## The Data Structure

A single binary data structure accumulates all game state. It contains:

- **RNG seed** — enables complete deterministic replay
- **Piece input log** — rotation state (2 bits) + column position (4 bits) per piece = 6 bits per placement
- **Running score / lines / level** — redundant cross-check data
- **Piece count** — establishes the frame of the game

This structure is updated with every piece placement.

-----

## The Hash

At every piece placement, the entire data structure is processed through SHA to produce a 32-bit digest.

That digest is encoded as a **5-character base-40 code** and displayed live on the game canvas at all times.

### Base-40 Character Set

Characters are selected for **visual unambiguity** — no characters that can be confused with each other under degraded conditions (no 0/O, no 1/I/l, etc.). This character set was originally designed for the Rush 2049 arcade system in 1999.

-----

## Snapshot Hash / Terminal State

The hash is a **snapshot hash** — it reflects cumulative game state at each piece placement and updates continuously.

The **final hash** is produced when the board rejects the next piece — the natural terminal state defined by the game itself. This is the authoritative score receipt.

**Intermediate screenshots** contain a compact QR code updated every piece placement. They prove the game is authentic at that moment but may not contain sufficient data to reconstruct 100% of play for extraordinarily long games.

**The final screenshot** generates a full receipt QR containing the complete data structure. For human-achievable Tetris scores — bounded by the NES kill screen around level 29-30, approximately 300-400 pieces — a complete game fits comfortably within a single QR code. The design goal is that **every screenshot contains the complete game state** up to that moment. For human play this is achievable. The boundary exists but may never be practically encountered.

This means:

- Any mid-game screenshot is a partial proof of work
- The final screenshot is the complete verifiable record
- You cannot fake a mid-game screenshot without reconstructing the entire valid game history that produces the correct hash at that exact piece count

-----

## Replay

Because the data structure contains the RNG seed and complete input log, any verified game can be replayed in full. Replacing the live RNG with a seeded deterministic path produces an identical game from the same inputs.

A very small amount of data encodes an entire high-level game. The receipt is compact by design.

-----

## Identity

Player name is **display-only**. It is not part of the hash or the data structure. A player can change their name at any time and all of their scores update accordingly.

This is a deliberate design decision: a person deserves the right to change their name before or after claiming a score. The score is verified by the game data. Identity is a separate concern.

-----

## Platform Vision

Tetris is the first game in this system because its input space is small, compressible, and bounded by human physical limits. It is the ideal proof of concept for a platform where:

- Human skill generates verifiable proof of work
- That proof has economic value
- The work itself is enjoyable and meaningful
- AI serves as an ever-raising bar that keeps human achievement meaningful

Any game with a bounded input set and deterministic replay is a candidate for this receipt architecture. Tetris proves it works.

-----

## Collaboration

If you want to contribute to CELLTOWER or build on this receipt system:

- The data structure definition is the foundation — everything else derives from it
- The base-40 character set is fixed — modifying it breaks existing receipts
- The RNG seed path must remain deterministic and stable — any change breaks replay
- `score.html` is a standalone file — it does not depend on the game running
- The game logic must not permit exploitable states — cryptographic soundness and game integrity are both required
